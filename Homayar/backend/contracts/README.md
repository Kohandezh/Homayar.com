# API contracts

`ingestion-v1.openapi.json` is the published OpenAPI contract of the asynchronous
ingestion API. The Python client in `Homayar/sdk/python/` is written against it.

## What it covers

Twelve operations, and only these:

- Upload: `POST /api/v1/uploads`, `POST /api/v1/voicemails`
- Track: `GET /api/v1/meetings/{meeting_id}`, `GET /api/v1/meetings/{meeting_id}/job`,
  `GET /api/v1/ingestions`, `GET /api/v1/ingestions/{ingestion_id}`
- Results: `GET /api/v1/meetings/{meeting_id}/` `transcript`, `summary`, `actions`,
  `evidence`, `quality`, `export`

Plus every schema they use, the bearer security scheme, and the error responses. Other
routes are not part of the contract, so changing them does not touch this file.

## How it is built

`openapi_contract.py` reads the live `app.openapi()`, keeps the twelve operations, and
adds what FastAPI cannot see from the code:

- the error responses of each operation, all in the `{"error": {...}}` envelope that
  `backend/main.py` sends (this also replaces FastAPI's own 422 schema, which the app
  never sends);
- the `Retry-After` header on `429` and `503`;
- the real media types of `/export`;
- the descriptions of auth, the 202 then poll then results flow, idempotency and retries.

These live in tables in `openapi_contract.py`. The routers are not changed.

The tables never hide the live schema. A status from the table is added only when the
route does not document that status itself. The one exception is FastAPI's default
`422`, which is replaced. The `/export` media types replace only FastAPI's empty default
`200`. If a route starts to document a status that the table also names, the build stops
with a `LookupError` that names the operation and the status. Then remove that status
from the table, and the route's own entry goes into the contract.

## Check and regenerate

Run from `Homayar/`:

```bash
uv run python -m backend.contracts.openapi_contract --check   # exit 1 and a diff when stale
uv run python -m backend.contracts.openapi_contract --write   # regenerate the file
```

`backend/tests/test_openapi_contract.py` runs the same check in CI. If it fails, look at
the diff. If the change is deliberate, run `--write`, bump the version as below, and
commit the file with the change.

## Versioning

`info.version` is the contract version. It is separate from the app version.

- Additive change (a new optional field, a new operation, a new error code): bump the
  minor, for example `1.0.0` to `1.1.0`. Existing clients keep working.
- Breaking change (removing or renaming a field, a new required parameter, a changed
  status code): do not edit this file. Publish `ingestion-v2.openapi.json` under a new
  `/api/v2` prefix and keep v1 working until clients move.

The version is `CONTRACT_VERSION` in `openapi_contract.py`.
